# Iron Condor — call skew 感度分析（2026-07-18）

## 目的

`callSkewSlope: 4.05` は**低 VIX（~11-13%）の単一スナップショット**較正であり regime 依存
（[us-iron-condor-config.ts](../../src/backtest/us/us-iron-condor-config.ts) の caveat / KOH-544）。
IC の収益の約半分は call 側プレミアムに依存するため、この未較正パラメータに対して
tail-test 判定がどれだけ頑健かを測定する。

put-only credit spread は「flat-IV 前提でクレジットを ~20% 過大評価」により edge が消滅した。
call 側で同じ故障モードが起きていないかの確認が本分析の主眼。

## 事前登録した判定基準

結果を見てから閾値を動かさないため、実行前に以下を固定した。

- `--call-slope 5.2` で 7/7 維持 → 本番化継続
- 5.2 で FAIL → **call 側 edge は skew 前提に依存。本番化を取り下げ**
- 6.3（put と同等）まで維持 → 構造 edge は本物

## 方法

```bash
npm run tail-test:iron-condor                        # baseline
npm run tail-test:iron-condor -- --call-slope <s>    # s = 4.5 / 5.2 / 6.3 / 8.0
```

期間 2007-01-03 ~ 2026-07-18、他パラメータは `US_IRON_CONDOR_BACKTEST_FIDELITY` 既定値。
`skewedIvMonotonic` は slope を上げると高 strike（call）側の IV が下がるため、
slope↑ = call クレジット減 = ストレス方向。

## 結果

| call slope | 対現状 | トレード数 | Win | PF | CAGR | MaxDD | CVaR5% | テールDD | 判定 |
|---|---|---|---|---|---|---|---|---|---|
| **4.05**（現状） | — | 441 | 80.7% | 1.83 | 7.03% | 21.2% | -$207 | 13.5% | ✅ 7/7 |
| 4.5 | +11% | 454 | 79.5% | 1.65 | **6.31%** ❌ | **26.6%** ❌ | -$217 | 12.1% | ❌ 5/7 |
| 5.2 | +28% | 292 | 75.3% | 1.38 | **3.51%** ❌ | **51.4%** ❌ | -$209 | 16.4% | ❌ 5/7 |
| 6.3（put 同等） | +56% | 287 | 71.4% | **1.09** ❌ | **0.25%** ❌ | **47.0%** ❌ | -$216 | 17.7% | ❌ 4/7 |
| 8.0 | +98% | 253 | **68.8%** ❌ | **0.93** ❌ | **-2.34%** ❌ | **56.7%** ❌ | -$171 | 20.4% | ❌ 3/7 |

閾値: Win ≥70% / PF ≥1.3 / CAGR ≥6.5% / MaxDD ≤25% / CVaR5% ≥-$250 / テールDD ≤30% / テールPnL% ≥-50%

## 判定：FAIL（本番化を取り下げ）

事前基準は「5.2 で FAIL なら取り下げ」だったが、**4.5 で既に FAIL**。
call skew を 11% 動かしただけで 7/7 → 5/7 に崩れる。

### 1. baseline は閾値の崖のふちにある

CAGR 7.03% に対し閾値は 6.5%、余裕は **+0.53pp のみ**。しかもこの閾値自体、
IC のために 10% → 6.5% に引き下げたもの。put 側は実 fill との乖離が 21.2% 実測されており
（[credit-divergence-2026-07-12.md](../paper-trading/credit-divergence-2026-07-12.md)）、
較正誤差 11% は現実的な範囲。**安全余裕が存在しない。**

### 2. MaxDD の悪化がテール期間の外で起きている

slope 5.2 で MaxDD が 21.2% → 51.4% に飛ぶ一方、**テール期間 DD は 16.4% に留まる**。
つまり最大ドローダウンは 2008 / 2020 / 2022 の危機局面ではなく**平常時**に発生している。
「静かな相場でプレミアムを積む」という戦略の想定と整合しない挙動であり、
テール検証だけでは捕捉できないリスクが存在する。

### 3. トレード数が非単調（441 → 454 → 292）

→ 追加調査の結果、**当初の仮説（strike 選択への影響）は否定された**。下記「追加調査」参照。

## 結論

**IC の tail-test 合格は、未較正のボラティリティ・モデルによって生成されていた可能性が高い。**
put-only を殺した故障モードと同一であり、IC はその教訓を put 側にのみ適用し、
収益の半分を担う call 側に同じ穴を残したまま本番戦略化されていた。

# 追加調査（同日）— トレード数非単調性の切り分け

## 当初仮説は否定

「slope がデルタ経由で strike 選択を動かしている」という仮説は**誤り**だった。
[condor-signal-generator.ts:84](../../src/backtest/iron-condor/condor-signal-generator.ts) に明示:

> strike 選択は flat IV（live と同じ delta ベース）。クレジット評価だけ skew を適用する。

`findStrikeForTargetDelta` には flat `iv` が渡されており、**skew は行使価格に一切影響しない**。
トレード数の変動は同ファイル 121 行の `SKIP_LOW_CREDIT`（クレジット薄で見送り）と、
そこから生じる**経路依存**（現金・建玉数・DD stop の発動タイミングのズレ）による。

## 代わりに判明したこと — DD hard stop がピークをリセットする

→ **KOH-567 に分離して記録**。要点のみ:

`dd-stop.ts` はクールダウン明けに `runningPeak` を下がった現在値にリセットするため、
`ddStopThreshold: 0.15` は累積損失の床として機能しない。slope 8.0 では 14 回のリセットで
真の MaxDD が **56.7%** に達した（equity ピーク 3465 → 最終 2080）。
「テール期間外で MaxDD が悪化する」現象（本レポート上部の問題 2）の正体はこれであり、
危機局面ではなく**平常時の階段状の減価**だった。

ただし baseline（4.05）では発動 2 回に留まり **MaxDD 21.2% は本物**。
劣化時にのみ効く潜在的な増幅機構である。

### これはバグではない

KOH-450 のとおり、当初の reentryPct 設計にあった **stuck state 問題**を回避するため、
cooldown + ピークリセットが意図的に選択されたもの。
`__tests__/dd-stop.test.ts:68` に仕様として明示されている。

### 代替案の検証（実装は revert 済み、不採用）

| mode | slope 4.05 | slope 5.2 | slope 8.0 |
|---|---|---|---|
| current | PF 1.83 / 7.03% / DD 21.2% / 441本 → ✅7/7 | 1.38 / 3.51% / 51.4% / 292本 | 0.93 / -2.34% / 56.7% / 253本 |
| A: ピーク維持 | 1.98 / **6.42%** / **17.2%** / 320本 → ❌6/7 | 1.69 / 3.44% / **17.4%** / 199本 | 0.74 / -1.03% / 24.5% / **47本** |
| B: cap 30% | current と同一 | 0.45 / -1.80% / 37.3% / **33本** | 0.47 / -2.65% / 41.8% / 60本 |

- **A** は DD 制御としては機能する（51.4% → 17.4%、PF も改善）が、KOH-450 が解決した
  **stuck state を再導入**する（slope 8.0 で 47 本 = 実質停止）。
- **B** は cap にラッチして恒久停止し、かつ停止後も既存建玉の出血で cap を超える（37.3%）。

**判断: (a) 現状維持 + 記録のみ。コード変更なし**（詳細と根拠は KOH-567）。

## 本取り下げ判断への含意

A（真のハードストップ）の下では **baseline でも CAGR 6.42% < 閾値 6.5%** となり不合格。
すなわち IC の不合格は call skew 単独の問題ではなく、
**現状の合格は「DD stop が損失を忘れて取引を再開する」挙動にも支えられていた**。
取り下げ判断は補強される。

なお A の CAGR 低下には「stuck state で本来の取引機会を撃たなくなった」分も含まれるため、
この数字を「真の実力」と解釈することはできない。両者の切り分けは未了。
